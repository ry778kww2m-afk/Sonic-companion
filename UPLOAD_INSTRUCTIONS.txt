C. RUN AUDIO LAB FOR THE TARGET RECORDING
1. Open the existing site at /Sonic-companion/audio-lab/ in Safari.
2. Select the authorized local audio file of the original 1959 studio “So What” recording from Kind of Blue.
3. Enter the deployed Worker base URL and AUDIO_LAB_TOKEN.
4. Enter the Spotify track URL for that same recording.
5. Confirm recording identity and consent to sending audio excerpts to OpenAI.
6. Run “Analyse with GPT-Audio 1.5”. The engine scans 30-second windows with 8-second overlap (22-second stride), up to four windows concurrently. Every window gets a primary pass and a mandatory independent ensemble pass. Thin/narrow results get an adaptive third depth pass. A 9½-minute recording uses 26 windows and therefore at least 52 model calls; adaptive depth can add more.
7. The analysis must pass all publication checks: at least four distinct model moments per minute (38 for 9½ minutes), no silent gap longer than 30 seconds, and at least one event in every overlapping window. Four or six moments are rejected. The app does not manufacture filler to meet the gate.
8. Review moments and timestamps. Tap “Publish to original app”. This stores the record in the same browser origin. Then open/refresh the main app and play the exact Spotify track. Main app should show a badge like “AUDIO LAB · GPT-AUDIO 1.5 · 38 MOMENTS” and metadata containing “BUILD v1.0.10 · BRIDGE 2.1.0”. Model guides automatically open in Full view, where every cue card has its own countdown/progress bar.

D. TROUBLESHOOTING USING THE VISIBLE BUILD MARKERS
- If the main app does not show BUILD v1.0.10, it is not serving the new frontend (or an old cache/service worker is still intercepting it).
- If the metadata says BRIDGE MISSING or another bridge version, the frontend and bridge deployment are incomplete or mismatched.
- If it says “no matching record”, the Audio Lab record was not published in the same browser origin/profile, or the Spotify track ID did not match.
- If it says “duration mismatch”, the local file and Spotify duration differ by more than three seconds; do not override this silently.
- If Audio Lab reports fewer than 38 moments for a 9½-minute file, or fails coverage, Publish remains disabled. Do not download/import sparse output as a complete guide.
- The version badge and actual cue count make it possible to distinguish an old build from a successfully loaded Engine 2.1 record.

E. WHAT IS AND IS NOT PROVEN
- Automated QA: `npm test` runs nine Node.js suites. The final suite runs the real v2.1 bridge and real `renderDynamicGuide()` function using a test-only 9½-minute/38-event fixture; it asserts 38 cue cards and 38 individual progress bars. This fixture is only in tests and is never app content.
- No genuine So What model output is included in the ZIP. No actual audio file or live API credentials were available to run a real listening analysis here.
- Automated tests do not prove musical correctness, exact local-file/Spotify-master identity, physical iPhone Safari behavior or successful deployment.
- Model confidence/timestamp confidence are self-ratings, not statistically calibrated probabilities.
- AUDIO_LAB_TOKEN is browser-visible and is not production authentication. Apply rate limiting and per-user authorization before exposing this broadly.
