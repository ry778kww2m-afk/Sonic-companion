SONIC COMPANION v1.0.3 — FAIL-CLOSED GUIDE PROVENANCE
BUILD DATE: 2026-10-31

PURPOSE
This is an overlay update for an existing Sonic Companion GitHub Pages repository. It contains the complete root application index.html, the Audio Lab page, the bridge, tests and deployment instructions. It is not a replacement for the whole repository.

WHAT CHANGED
- Normal Spotify playback and the guide-lookup button no longer call buildMockGuide() as a fallback.
- The existing So What / Kind of Blue demonstration fixtures remain in the source for demo/QA only; normal production paths do not load them.
- An unknown recording now displays an explicit unavailable-guide state rather than a plausible-looking mock guide.
- The one explicitly supported offline curated Rachmaninoff album-section guide remains available and is labelled as curated offline content, not audio recognition.
- Audio Lab may populate an otherwise-empty guide with DSP signal-change candidates only when the imported record has the exact Spotify track ID and duration within +/-3 seconds.
- DSP candidates are labelled as measured signal changes. They do not identify instruments, solos, performers, formal sections or musical causes.
- The recording-match confirmation remains manual. The app does not acoustically fingerprint the Spotify stream.
- Live web research is not configured in this build. The interface says so rather than pretending to perform research.

BEHAVIOUR AFTER DEPLOYMENT
- Playing So What should no longer display the old hard-coded opening / two-chord editorial cue sequence.
- Without a matching Audio Lab JSON record, the app should say that no guide is available for that recording.
- With a valid imported Audio Lab record, the app should display only measured DSP candidates and explicitly label them as such.
- The Rachmaninoff offline curated section guide is still available when the exact supported album identity matches. It describes the complete album-section track and is not audio event recognition.

TESTS
Run from the repository root with Node.js 20 or newer:

The included build test validates complete file presence, v1.0.3 version consistency, inline JavaScript syntax, no mock-builder calls in the normal lookup or playback paths, Spotify auth/playback safeguards and the Audio Lab storage/publisher contract.
The integration test validates analysis-only shell import, exact Spotify track-ID matching, +/-3 second duration matching, rejection of mismatches, candidate-only labelling, preservation of curated cues, duplicate prevention and invalid-record rejection.

LIMITATIONS / NOT CLAIMED
- Automated tests passed in Node.js 22.16.0.
- No live GitHub deployment, iPhone Safari, Spotify playback session or cross-device Audio Lab import was run in this environment.
- The Audio Lab analysis is local DSP. It detects signal-change candidates; it does not semantically recognize musical events.
- This release stops false mock claims. It does not yet provide a live researched editorial guide for So What. That requires a separately implemented and tested research-service integration with citations and recording-specific provenance.
