SONIC COMPANION v1.0.8 — AUDIO LAB ENGINE 2.0

This is a targeted overlay. Do not replace the whole GitHub repository.

A. CLOUDFLARE WORKER (separate deployment)
1. Back up the currently deployed sonic-companion-research Worker source.
2. Replace the Worker entrypoint with worker/index.js from this package.
3. Keep OPENAI_API_KEY as a Worker secret. Never place it in GitHub Pages or browser code.
4. Configure ALLOWED_ORIGIN to the exact static-site origin (scheme + host only, no repository path).
5. Configure AUDIO_LAB_TOKEN as a random secret of at least 32 characters. It is an internal POC gate, not production user authentication.
6. Deploy the Worker. Open <worker-base-url>/health and verify that the OpenAI key, allowed origin and Audio Lab token are configured.

B. GITHUB PAGES (preserve existing repository)
Replace/add only these paths from this package:
- /index.html
- /audio-analysis-bridge.js
- /audio-lab/index.html
- /worker/index.js (source for the separate Worker deployment; it is not served as a Pages Worker)
- /package.json and /tests/ (optional, for local automated QA)

Preserve unrelated files and folders, especially Spotify OAuth configuration, manifest, service worker, icons, translation assets and the existing Worker deployment configuration. Keep the paths exactly as shown. Do not delete the existing repository's other files.

C. RUN AUDIO LAB FOR THE TARGET RECORDING
1. Open the existing site at /Sonic-companion/audio-lab/ in Safari.
2. Select the authorized local audio file of the original 1959 studio “So What” recording from Kind of Blue.
3. Enter the deployed Worker base URL and AUDIO_LAB_TOKEN.
4. Enter the Spotify track URL for the same recording.
5. Manually confirm recording identity and explicitly consent to sending audio excerpts to OpenAI.
6. Run “Analyse with GPT-Audio 1.5”. The engine scans overlapping 30-second windows with an 8-second overlap. Each window gets a primary pass; windows with fewer than three primary events get a complementary detail pass. A 9½-minute recording uses 26 primary windows and may require up to 26 additional detail calls.
7. The result must pass all coverage checks before the Publish or Download controls are enabled. For a 9½-minute recording, the minimum publishable count is 29 events, with no silent gap over 45 seconds and no uncovered analysis window. If the model does not find sufficient defensible content, the record is rejected instead of padded.
8. Listen through the generated timestamps and descriptions before publishing. The bars show each moment’s own time window; the app’s Spotify countdown and overall progress are retained.

D. WHAT IS AND IS NOT PROVEN
- Automated QA: all eight included Node.js suites must pass (`npm test`).
- This code release does not include genuine So What model output. No test fixture is used as app content.
- A successful local test run does not prove live OpenAI output quality, exact local-file/Spotify-master identity, iPhone Safari compatibility or successful deployment. Those require the user's real recording, API secrets, live Worker and physical iPhone session.
- Model confidence and timestamp confidence are self-ratings, not statistically calibrated probabilities.
- The tester token is browser-visible and is not a substitute for production authentication. Configure rate limiting before exposing the Worker broadly.
